KEEP 묶음 — 같은 파일, 다른 지키기

파일이 사라지지 않고 계속 남아 있다. 이 결과는 같고, 무엇을 막으려고, 어디에, 얼마나 오래 남기는지만 바꾸면 keep · retain · store · save · preserve로 갈린다. keep은 목적을 말하지 않고 계속 갖고 있음만 그린다.

장소

1. 무엇인가 — "계속 남아 있음"에 목적(HOW)이 붙는다

이 묶음의 BASIC/RESULT는 TARGET을 잃거나 버리지 않고 계속 보유하거나 원하는 상태로 유지함 = KEEP이다. 여기에 예상되는 손실과 유지 목적이 붙는다. 노트의 Shared Result와 비교표를 식으로 옮겼다.

KEEP+계속 보유, 목적 미지정=KEEP KEEP+삭제·이전 가능성에도 보유=RETAIN KEEP+나중 사용을 위해 정해진 곳에=STORE KEEP+손실을 막고 다시 쓰게 기록=SAVE KEEP+오랫동안 내용·상태가 안 변하게=PRESERVE

14 GIVE의 반대쪽이다. 거스름돈을 상대에게 넘기지 않고 그대로 가지라고 할 때 Keep the change. 넘기면 give, 남기면 keep.

2. 그림에서 일어나는 일

  • 계속 가짐 → 월요일에도 금요일에도 폴더에 그대로. 왜인지는 말하지 않는다. Keep the file until Friday.
  • 지울 수 있는데 남김 → 삭제 정책 휴지통이 기다리지만 방패가 막는다. The school retained the file.
  • 정해진 곳에 넣어 둠 → 보관함 서랍 "2024 자료"에. 나중에 꺼내 쓰려고. She stored the file in the archive.
  • 날아가지 않게 기록 → 정전 번개가 쳐도 저장 표시 덕에 살아남는다. Save the file before closing the program.
  • 원래 그대로 오래 → 1900년 문서가 유리 안에서 2026년에도 같은 모습. The archive preserved the original file.
  • 어느 장면이든 "파일이 계속 남아 있다"는 맞으니 keep도 쓸 수 있다. 그래서 KEEP 칩은 늘 켜진다.

3. keep이 그리는 그림 — 상태가 끊기지 않고 이어짐

keep의 그림은 물건을 갖고 있는 것만이 아니다. 지금 상태가 끊기지 않고 계속 이어짐이다. 그래서 뒤에 형용사·-ing·장소가 붙어 회화에서 아주 바쁘다.

07 COMMIT과 견줘 보면: save는 지금 모습을 덮어써 남김, git commit은 되돌릴 수 없게 기록에 넘김. 둘 다 "남김"이지만 commit은 KEEP 묶음 밖이다.

4. 무엇이 다른가 — 질문을 따라 고른다

점선 테두리가 KEEP 묶음이다. 남기지 않고 상대에게 넘기면 테두리 밖 문으로 GIVE 묶음에 간다.

5. 실제 문장으로 — 뒤에 무엇이 붙나

다섯 다 남기는 것을 목적어로 받는다. 어디에는 in · on · to, 얼마나는 for로 붙인다. keep만은 목적어 대신 -ing · 형용사도 받는다.

6. 몸으로 해 보기

  • KEEP — 펜을 쥔 손을 가슴 쪽으로 당겨 그대로 둔다.
  • RETAIN — 누가 가져가려는 펜을 손바닥으로 막고 내 쪽에 둔다.
  • STORE — 펜을 서랍에 넣고 닫는다. 나중에 꺼낼 것.
  • SAVE — 키보드에서 Ctrl + S를 누르는 시늉.
  • PRESERVE — 두 손으로 펜을 감싸 덮는다. 아무것도 닿지 못하게.
