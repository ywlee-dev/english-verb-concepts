# BRING Family

## Shared Event Backbone

## 상황에서 꺼내기 — 설명을 보기 전에

사무실에 필요한 물건이 움직이는 경로를 떠올려 보자.

1. 창고의 소포를 사무실로 가지고 온다.
2. 사무실에서 창고까지 가지러 갔다가 돌아온다.
3. 지정 고객에게 소포를 건네 전달을 마친다.
4. 택배망에 소포를 맡겨 다른 도시로 보낸다.

<details><summary>동사와 선택 이유 보기</summary>

1. `bring`: Please bring the package to the office. 기준 장소 쪽으로 오게 한다.
2. `fetch`: I'll fetch the package from storage. 가지러 가는 경로가 포함된다.
3. `deliver`: The driver delivered the package to the customer. 목적지나 수령인에게 전달한다.
4. `ship`: The company shipped the package to Busan. 운송 체계에 넘겨 보낸다. 도착까지 뜻하지는 않는다.

</details>

내 장면으로 바꿔 보기: 최근 물건 하나를 옮긴 일을 떠올리고, 어디로 가져왔는지 또는 어디로 보냈는지 말해 보자. `ship`은 개념상 `send` 쪽에 더 가깝다.

agent가 TARGET을 기준 사람이나 목적지 쪽으로 오게 만든다.

| Verb | Package example | Distinctive Route / Purpose |
|---|---|---|
| BRING | bring the package to the office | TARGET을 목적지 쪽으로 동반 이동 |
| FETCH | fetch the package from storage | 가지러 간 뒤 가져오는 왕복 구조 |
| DELIVER | deliver the package to the customer | 정해진 수령인에게 전달 완료 |
| SHIP | ship the package to another city | 운송 조직·수단을 통해 보냄 |

```text
BRING + 가지러 갔다가 돌아옴 = FETCH
BRING + 지정 수령인에게 완료 = DELIVER
BRING + 조직화된 운송 수단   = SHIP
```

## Scenario contrast

창고의 package를 사무실로 가져오면 BRING, 먼저 창고까지 가서 찾아 돌아오면 FETCH, 고객 서명까지 받아 전달을 완료하면 DELIVER, 먼 도시로 택배망을 이용해 보내면 SHIP이 된다. 출발 전 이동·수령 완료·운송 시스템이 HOW를 결정한다.

## 분류 경계

`SHIP`은 발송자의 동반 이동이나 목적지 도착을 뜻하지 않는다. 이 노트는 물건 이동 방식을 비교하는 학습용 배치로만 두며, 엄밀한 상위 사건은 `BRING`보다 `SEND`에 가깝다. `DELIVER`는 지정 수령인에게 도달한 결과까지 포함한다.

## Sound & Forms reference

`bring → brought → brought`는 불규칙 변화다. `fetch`와 `deliver`는 규칙 변화이고 `ship → shipped → shipped`는 `p`를 겹친다. 발음·형태 확인: [Cambridge: bring](https://dictionary.cambridge.org/us/dictionary/english/bring), [fetch](https://dictionary.cambridge.org/us/pronunciation/english/fetch), [deliver](https://dictionary.cambridge.org/us/pronunciation/english/deliver), [ship](https://dictionary.cambridge.org/us/pronunciation/english/ship).
